## What the tests must do

MMDB test:
  - Reuse the data-loading and function-call code from the working probe
    above. Copy the probe's loader verbatim into a `TEST()` body.
  - Replace the probe's `std::cout << "PROBE: ..."` lines with `EXPECT_EQ`,
    `EXPECT_NEAR`, or `EXPECT_STREQ` against the measured oracle values.

Gemmi test:
  - Read the same PDB file (see the probe reference) via
    `gemmi::read_structure_file`.
  - Walk the gemmi hierarchy to the same logical object and call the
    refactored function. Assert against the same oracle values.

Both tests use `TEST()` or `TEST_F()` macros and must NOT mock anything or
construct synthetic mmdb / gemmi structures by hand.

## Required headers (use these exact spellings — nothing else from mmdb)

  MMDB test:  #include <gtest/gtest.h>
              #include <mmdb2/mmdb_manager.h>
              (plus the function's own header — see "Where the function lives")

  Gemmi test: #include <gtest/gtest.h>

Do NOT include `mmdb_model.h`, `mmdb_chain.h`, `mmdb_atom.h`,

standalone public headers.

## Hard rules

- Every MMDB type in the MMDB test MUST be written with the `mmdb::`
  namespace prefix: `mmdb::Manager`, `mmdb::Model*`, `mmdb::Chain*`,
  `mmdb::Residue*`, `mmdb::Atom*`, `mmdb::Error_NoError`. There is no
  `using namespace mmdb;` in coot test code, so an unqualified `Manager`
  or `Chain*` will not compile.
- Use ONLY symbols and members that appear in the API reference, the
  function source code, or the working probe. Do not invent function
  names, member names, or types.
