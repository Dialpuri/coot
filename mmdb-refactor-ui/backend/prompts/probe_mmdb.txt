## What the probe must do

1. Contain a single `int main(int, char**)`. No gtest, no `TEST()` macros.
2. Load coordinate data from this exact path:
       `$pdb_path`
   using `mmdb::Manager::ReadCoorFile`. Check the return code and bail out
   on error.
3. Navigate the loaded manager (model → chain → residue → atom) until you
   have the real object(s) the function expects. Do NOT build any synthetic
   mmdb structures by hand.
4. Call `$function_name` with those real inputs.
5. Print the function's output to stdout, one value per line, each prefixed
   with `PROBE: `:
       std::cout << "PROBE: return_value=" << result << std::endl;
   - For vectors / lists, print the size first then each element:
       PROBE: size=3
       PROBE: elem[0]=...
   - For structs, print each field on its own PROBE line.
   - For floats use `std::setprecision(6)`.
6. Return 0 on success, non-zero on any error.

## Hard rules

- Use ONLY symbols, types, and members that appear in the API reference above
  or in the function's source code. If you are not sure a method exists, do
  not call it. Inventing API names will fail compilation and waste a retry.
- Do NOT include `<gemmi/...>` headers. Gemmi must not appear anywhere in the
  probe source.
- Do NOT mock, stub, or reimplement the function under test.
- Do NOT include headers that are not in the "Real includes from the source
  file" block above unless they are part of the C++ standard library.

## Output format

Output ONLY the probe source code inside a single ```cpp``` block, starting
with the includes. Do not output any other text before or after the block.
